# CRML-CT screen, converter fix and demo check (2026-10-20)

## W1 CRML-CT: same code path, no affected patient
`glassbox.audit.crml.load_seg_masks` places every SEG frame on the CT slice by its referenced SOP instance UID and never reads the SEG's own ImagePositionPatient, so it has the same blind spot as `ignore_spatial_locations=True`. Header screen of **all 197 patients** (`scripts/dq_crml_offset_screen.py`, manual SEG series chosen by the W1 rule, `crml/crml_offset_screen.csv`): in-plane and through-plane offsets between each SEG frame's position and the CT instance it references are **0.0 mm for every frame of every patient**; all frames match a CT instance; the FrameOfReferenceUIDs agree in all 197. **Flagged (> 1 mm): 0.** No re-conversion, no change to the W1 shares, impact rule not triggered.

## Converter fix at the source
- New `glassbox/data/seg_offset.py`, wired into `scripts/convert_heldout.py` (UID route): the SEG's declared in-plane offset from the referenced CT instances is now ALWAYS computed from the headers and applied (whole voxels; refused if not constant across frames); every non-zero shift is logged with the case ID and the offset in mm (`SEG-OFFSET FALLBACK ...`), and a failure of the UID route is logged before the geometry fallback (`GEOMETRY FALLBACK ...`). The label placement is recorded in `segments.json` (`seg_placement`).
- **Finding:** dropping `ignore_spatial_locations=True` alone would NOT have fixed HCC_019: highdicom's strict read accepted a synthetic SEG that was 5 mm off its CT (`tests/test_seg_offset.py`), so the offset has to be applied explicitly.
- `tests/test_seg_offset.py` covers the pure helpers and both paths with a synthetic DICOM-SEG built with highdicom (matched positions: no shift; known 5 mm offset: shifted by 5 voxels). It is skipped where pydicom / highdicom are absent and was run on the instance (2 passed).
- **75-case UID-route re-run with the fixed converter** (`scripts/dq_verify_fixed_converter.py`, `verify_fixed_converter.json`): the label of every case is identical to the stored original conversion except **HCC_019_773068** (offset -25.0 mm in y, shift -36 voxels), whose label equals the corrected conversion exactly. The 14 position-matched cases use `convert_heldout_clean.py`, which places frames by position; their header offsets are 0 (`source_check_clean89.json`).
