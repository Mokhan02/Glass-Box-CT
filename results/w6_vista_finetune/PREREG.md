# W6 PREREG: fine-tuning NV-Segment-CT (VISTA-3D, `vista3d132`) with bright-tumour augmentation, validated on WAW-TACE and HCC-TACE-Seg
Status: DRAFT for sign-off, 2026-11-08 (frozen only when committed with its hashes). Research use only; no clinical claims. Basis: `results/w6_vista_finetune/SCOUTING.md` (sources quoted there). **No GPU has been used for W6; nothing is trained or evaluated.** The W4b PREREG (`results/w4b_waw/PREREG.md`) holds the within-tumour test of the fine-tuned arms.

## 1. Question and predictions (stated before any run)
**Q1.** Does fine-tuning VISTA-3D on tumours made brighter than the liver (MSD Task03 only) close the bright-versus-dark gap on real tumours of an independent cohort (WAW-TACE) and of the original cohort (HCC-TACE-Seg), compared with fine-tuning on darkened tumours (SHAM) and with plain fine-tuning (PLAIN)? **Prediction: yes**, in the direction W5 found for nnU-Net (BRIGHT-50 CONFIRMED on WAW-TACE: detection gap D0 +0.626 -> BRIGHT-50 -0.036 on the arterial series); SHAM and PLAIN keep the gap of the baseline (about +0.58 detection on all tumours, W4 (a)). The size of the effect cannot be predicted (W5 trained from scratch; here a few thousand iterations from a strong initialisation).
**Q2 (mechanism, hypothesis from W2-M / W3 Stage 2 "represented in the late features, not decoded by the head").** Does a decoder-only fine-tune (encoder frozen; auto-branch decoder and class head trainable) recover most of the full BRIGHT effect? **Prediction (the researcher's hypothesis): yes.** Counter-evidence stated now: W2-M patching of dark mid-encoder features into the bright run restored 0.79 of the coverage drop (results/SUMMARY.md, test D), so the encoder may matter; an answer of "no" is an informative result.
**Q3 (safety).** Does the fine-tune forget other classes or add false positives? (section 7.) A fix that fixes the gap and costs forgetting is reported as **"fix with forgetting cost"**, with both numbers, in the title of its result; it is never reported as a fix alone.

## 3. Recipe common to all arms (official continual-learning settings, `scripts/trainer.py` / `configs/train.json` + `train_continual.json` of NVIDIA-Medtech/NV-Segment-CTMR)
`finetune: true` from `vista3d_pretrained_model/model.pt` of nvidia/NV-Segment-CT (the weights of W1 to W5; sha256 recorded in the run report); AdamW, **learning rate 5e-5 constant** (the official continual setting: `learning_rate 5e-05`, `lr_schedule#activate false`, so no schedule), weight decay 1e-5; loss `DiceCELoss` (sigmoid, squared_pred, `smooth_dr 0.01`, `smooth_nr 1e-4`: the continual overrides of the base `1e-5` / `0`); **8,000 iterations** (the run stops at iteration 8,000 through an Ignite handler; `epochs = ceil(8000 / n_train)` is only the upper bound), batch size 1, `num_patches_per_image 1`, **patch 128^3** (96^3 only if the smoke test runs out of memory, and then for ALL arms, decided before any arm trains), 1.5 mm isotropic, intensity window -963.8 to 1053.7 HU, AMP, `drop_point_prob 1`, `drop_label_prob 0` (automatic branch only; the official recommendation for automatic-only fine-tuning, set in `scripts/w6_overlay.json`). **Augmentations: exactly those of the official `train_continual.json` (verified from the file, bundle commit `cb921f5`):** `ClassesToIndicesd`, `RandCropByLabelClassesd` (uniform ratios over the classes present: background, liver, tumour; about one third of the crops are tumour-centred), then **the W6 edit (arms 1, 2, 4, 5 only, inserted right after the crop)**, `RandZoomd` (p 0.2, 0.8 to 1.2), `RandSimulateLowResolutiond` (0.2), `RandGaussianSmoothd` (0.2), `RandScaleIntensityd` (0.2), `RandShiftIntensityd` (0.2), `RandGaussianNoised` (0.2, std 0.2), then the label relabelling. `CacheDataset` with cache rate 1.0. **Transform order (amendment 1, before any run): the W6 edit runs on raw HU, BEFORE the bundle's intensity clip / rescale (`ScaleIntensityRanged`, clip true) and BEFORE every other intensity augmentation.** To make this literal, `ScaleIntensityRanged` is moved, for ALL arms (PLAIN too, so that every arm has the same order), from the cached deterministic chain to right after the random crop (and the edit); the training chain is therefore `LoadImaged, CropForegroundd, Orientationd, Spacingd, CastToTyped, EnsureTyped, SpatialPadd (image padded with the window floor, label with 0: the official padding value, now that padding precedes the rescale), ClassesToIndicesd, RandCropByLabelClassesd, [BrightTumourShiftd], ScaleIntensityRanged, RandZoomd, RandSimulateLowResolutiond, RandGaussianSmoothd, RandScaleIntensityd, RandShiftIntensityd, RandGaussianNoised, Relabeld`; the validation chain keeps the official order (`ScaleIntensityRanged` second). **Stated deviation from the official recipe, identical in all arms:** the window clip is applied after the 1.5 mm resampling instead of before it (the two differ only at air / bone interfaces, outside the liver). **The driver asserts this order before the first iteration and writes the transform list of the training and validation chains to the run report and to the smoke output.** The training seed is set through the bundle's `initialize` (`set_determinism(seed=S)`, overriding the bundle's seed 0); training is not bitwise deterministic. **Pinned stack (the bundle's own pins): `monai==1.4.0`, `pytorch-ignite` (version recorded), PyTorch as installed (the bundle metadata names 2.4.0, its requirements 2.0.1; recorded in the run report); in the CPU dry-run the bundle failed to instantiate its validation metric when `pytorch-ignite` was missing (the only failure found; MONAI 1.6.1 failed the same way and was not tested further, MONAI 1.4.0 with `pytorch-ignite` 0.5.1 ran).** **Checkpoint policy: the FINAL model (iteration 8,000) is saved by the driver; no checkpoint is chosen on WAW-TACE, HCC-TACE-Seg or any evaluation cohort, and none by validation score** (the bundle's validation handler also writes a best-by-validation `model_finetune.pt`; it is never used). Validation (the 10 fixed Task03 validation cases of fold 0, `val_interval` 10 epochs, not at start) is written for monitoring and sanity only; the official `val_interval 1` and `val_at_start true` are replaced by these for compute, for all arms. **Class-26 inference prompting is exactly the W4 route** (`glassbox.seg.w2_lib.Runner`: automatic class-prompt segmentation, whole-volume sliding window 128^3 with 0.3 overlap, probability > 0.5; class 26 for the tumour and class 1 for the alignment gate).
**Data.** MSD Task03 (131 labelled CTs), nnU-Net fold-0 split of W3 and W5 (`splits_final.json`; about 105 training cases; the validation cases are used only as in the previous paragraph). **No WAW-TACE, HCC-TACE-Seg, C4KC-KiTS or CRLM-CT case is used in training, validation, the augmentation statistics or any preprocessing.** Caveat stated: Task03 was part of VISTA-3D's original training (paper dataset table), so it is not new data to the model; the evidence of transfer is the held-out cohorts.

## 4. The label mapping and the loss: what was verified from the code (quoted)
**Question:** with label mapping `[[1,1],[2,26]]`, are the absent classes unsupervised or pushed toward background? **Answer, from the official continual configuration: classes that are not mapped are unsupervised; classes that are mapped but absent from a patch are (correctly) pushed to zero.**
- `train_continual.json`: `"label_set": "$[0] + list(x[1] for x in @label_mappings#default)"` and `"output_classes": "$len(@label_set)"`: with `label_mappings default [[1,1],[2,26]]` the label set is **[0, 1, 26]**. The mapping transform `monai.apps.vista3d.transforms.Relabeld` is the last transform of `train#random_transforms` (after the crop).
- `monai/apps/vista3d/sampler.py`, `sample_prompt_pairs`: `unique_labels = list(set(unique_labels) - (set(unique_labels) - set(label_set)) - {0})` (present and in `label_set`) and `background_labels = list(set(label_set) - set(unique_labels))` (in `label_set` but absent from the patch). Only classes of `label_set` can ever become prompts.
- `scripts/trainer.py`: `for id in range(len(prompt_class)): if prompt_class[id] == 0: continue; loss += engine.loss_function(outputs[[id]].float(), labels == prompt_class[id]); loss_n += 1.0`, `loss /= max(loss_n, 1.0)`: the loss exists only for sampled prompts; a prompt of an absent class has an all-zero target (a correct "no tumour here"), class 0 is skipped.
**So the other 130 classes receive no loss in the continual configuration.** **Trap (must be asserted):** the base `train.json` alone has `"label_set": null` and the trainer falls back to `label_set = np.arange(output_classes).tolist()` (all classes): every absent class would be prompted with an all-zero target and **pushed toward background** (catastrophic for unlabelled organs). **Therefore the run must use the continual configuration, and the preflight asserts `label_set == [0, 1, 26]`, with a unit test that 1,000 sampled prompt sets contain no class outside {0, 1, 26}** (both are implemented in `scripts/w6_train.py` and asserted before the first iteration). The unsupervised classes can still drift through the shared encoder (nothing anchors them): that is what the forgetting guard measures (section 7).
**A second, subtler issue (flagged, with a pre-set rule).** In MSD Task03 the liver label (1) EXCLUDES the tumour voxels (label 2); mapping `[[1,1],[2,26]]` teaches the liver prompt to output zero inside tumours. Whether VISTA-3D's own liver class includes lesions is not documented. **Rule, decided now and evaluated on the BASELINE only (before any arm trains):** on the Task03 validation cases, compute the fraction of ground-truth tumour voxels that the baseline's class-1 mask covers. **If it is at least 50% (VISTA's liver includes tumours), the mapping `[[1,1],[2,26]]` would teach a new convention, so ALL arms use `[[2,26]]` (label set [0, 26]; the liver class is then unsupervised; tumour-only supervision); otherwise `[[1,1],[2,26]]` as requested.** The decision and the measured fraction are logged before arm 1 starts; the same mapping is used for every arm.
**Tumour-centred sampling.** In the continual configuration the crop is `RandCropByLabelClassesd` with `num_classes 255` and `ratios` 1.0 for every class index (classes without voxels are skipped), applied to the LOCAL labels (the relabelling is the last transform): each patch is centred on a voxel of a class drawn uniformly from those present in the case, {background, liver, tumour}, so about one third of the patches of a case with tumours are tumour-centred (official default, unchanged; with the tumour-only mapping one half).

## 5. The augmentation (ported from W5, in physical units; code and phantom tests committed and hashed before any run)
Applied right after the random crop, **on the HU patch, before the bundle's clip / rescale and before every other intensity augmentation** (the edit does NOT clip; the `ScaleIntensityRanged(clip=True)` that follows does), on the local labels (1 liver, 2 tumour): with probability p = 0.25 **per patch** (one seeded Bernoulli draw per patch, as in W5; a patch that is chosen has ALL its qualifying tumour components edited, each with its own Delta), shift each tumour component (26-connected, at least 30 voxels) so that its mean HU equals the mean of the local liver plus Delta, Delta ~ U(+10, +60) HU for BRIGHT and U(-60, -10) HU for SHAM; the local liver is the liver voxels (tumour voxels excluded) within 8 voxels (12 mm at 1.5 mm; W5 used 12 voxels at about 1 mm) of the component, falling back to all liver voxels of the patch (at least 200) and otherwise leaving the component unchanged; Gaussian feathering of the component mask with sigma 1 voxel; (no clip in the edit). **Unit tests required before any run:** (i) phantom with two tumour components in a liver: the edited component's mean lies at liver mean + Delta (tolerance 2 HU); (ii) voxels outside the component and its feather are unchanged; (iii) the sign: BRIGHT raises and SHAM lowers; (iv) dtype, and in HU mode no clipping inside the edit (the bundle's rescale clips afterwards: tested with the bundle's transform); (v) determinism for a seed; (vi) the fraction of patches that are edited over 10,000 draws is 0.25 +/- 0.02 (and every qualifying component of an edited patch is edited); (vii) **parity with the W5 function** `shift_tumour_contrast` on the same phantom in HU space (same Delta, same mean shift), with the unit differences documented.

## 7. Forgetting guard (measured on the baseline and on every arm, same code, same cases)
| measure | data | rule |
|---|---|---|
| organ Dice (spleen 3, right kidney 5, left kidney 14, liver 1) | MSD Task09 spleen (41 cases), C4KC-KiTS (a fixed random 60 cases, seed fixed), MSD Task03 validation cases (liver) | **pass if each organ's mean Dice drops by at most 0.02 and the paired bootstrap CI lower bound of the change is above -0.03** |
| kidney tumour Dice (the W2 class) | C4KC-KiTS (the same 60) | side check, reported (not a pass criterion): an edit of liver tumours must not move another organ's tumour class |
| prediction drift of all supported classes | 20 fixed WAW-TACE CTs (seed fixed), official all-class prompts | Dice between the baseline's and the arm's prediction, per class. **Pass criterion (organs): drift Dice >= 0.95 only for classes whose median baseline volume on those 20 CTs is at least 10 mL (the volume floor, set now); classes below the floor are reported descriptively, with their volumes** |
| false positives | tumour-free Task03 livers (13 cases) and, in the WAW-TACE series, predicted class-26 voxels farther than 10 mm from any ground-truth tumour | predicted volume per case, baseline against arm; **pass if the arm's median is at most 1.25 x the baseline's** |
**Reporting rule, pre-stated:** an arm that closes the gap but fails any pass criterion is reported as **"fix with forgetting cost"**, naming the failed measures, in the headline of its result and everywhere it is quoted; an arm that passes all is "fix, no measured forgetting (within these measures)". Failing arms are never dropped, relabelled or analysed without this tag. A failed guard may trigger a pre-specified contingency only as a logged amendment before another arm trains (lower learning rate, encoder-frozen arm 4 already in the plan, a small replay set of other classes).

## 8. Evaluation and verdict rules
**Cohorts and pipeline.** WAW-TACE: exactly the W4 pipeline and cohort (297 kept tumours, 396 series, detection = coverage >= 0.10, `scripts/w4_waw_score.py`, alignment gate, the same sensitivities incl. 2 mm dilation, excluding gate failures; non-LAS series handling does not apply to VISTA, which reorients). HCC-TACE-Seg: the W3 pipeline (75 cases, 86 lesions) as the secondary replication. Gap = dark minus bright (positive: bright detected less); bright / dark by the contrast on the scored series; patient-clustered bootstrap, 1000 resamples for gaps and 2000 for the within-tumour tests, seeds from the SHA-256 of fixed names.
**Primary (c)-type test, arterial series of WAW-TACE (the W5 rule):** Delta = gap(BRIGHT-FT) - gap(SHAM-FT), paired patient bootstrap (same resampled patients), per metric (detection, Dice): **CLOSES if the CI upper bound < 0 and the point estimate <= -0.10; DOES NOT CLOSE if the CI lower bound > -0.10; INCONCLUSIVE otherwise.** Overall label: **CONFIRMED (detection and Dice / detection only / Dice only)**, **NOT CONFIRMED**, or **INCONCLUSIVE**, exactly as W5. Secondary: the same against PLAIN-FT (arm 3, if run) and, descriptively, against the baseline and against BRIGHT-FT-s2 (replication: the s2 arm must reach the same CLOSES verdicts against SHAM-FT; the difference between the two BRIGHT runs is the only seed-variance estimate).
**Q2 estimand (BRIGHT-DEC vs BRIGHT-FT).** R = [gap(PLAIN-FT) - gap(BRIGHT-DEC)] / [gap(PLAIN-FT) - gap(BRIGHT-FT)] on the arterial series for each metric, patient bootstrap of the ratio. **Evaluable only if the denominator's CI excludes 0** (BRIGHT-FT must reduce the gap against PLAIN-FT), otherwise NOT EVALUABLE. **DECODER SUFFICES if R >= 0.5 and the CI lower bound >= 0.25; ENCODER NEEDED if R < 0.5 and the CI upper bound < 0.75; INCONCLUSIVE otherwise.** (The hypothesis is DECODER SUFFICES.)
**The within-tumour test and the public models** are specified in the W4b PREREG; the W6 verdict does not depend on them.
**Reported always:** gap per arm and stratum (arterial-drawn / portal-venous-drawn), bright detection rates, the forgetting guard table, alignment-gate failure counts, compute and wall time, and every deviation.
