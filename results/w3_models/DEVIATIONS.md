## 1. HCC_019_773068 ground-truth label displaced 25 mm by our converter (found 2026-10-20 by the W3 alignment gate; classified converter bug)
- **What:** the UID-route converter read the DICOM-SEG with `ignore_spatial_locations=True` and so discarded a constant 25.0 mm offset between the SEG frames' ImagePositionPatient and the CT instances they reference. Only this case of the 89 clean cases is affected (all 89 checked at header level; the model-free screen's two other flags, HCC_012 and HCC_024, are false positives on visual review). Full evidence: `results/dq_hcc_labels/DQ_REPORT.md`.
- **Rule applied (the researcher's, fixed before the check):** converter bug -> fix, re-convert, re-run the affected cases, no exclusion. Corrected conversion written beside the original (`heldout_nii_fixed`); the original conversion is kept as the "as converted" sensitivity.
- **Effect:** the case's single cohort lesion changes from dark (-49.2 HU) to bright (+8.2 HU); it is a VISTA-3D miss either way. Headline sum-of-diameters bias moves at most 0.7 point (excluded) and 0.0 (corrected); no W1 / W2 v3 / W3 reference-row verdict changes category in any computed scenario -> RESEARCH_LOG footnote, no Evidence-page update (provisional on the corrected point-prompt W2 re-run).
- **Not applied, awaiting the researcher:** the PREREG_stage1 cohort (28 bright / 58 dark) would become 29 / 57 with the corrected case, and `glassbox/seg/w3_lib.py` (code hash in `code_hashes.txt`) would need a corrected-root override for this case. Proposed: apply the correction prospectively to W3 before any model A / model D cohort analysis, keep the as-converted result as a sensitivity row, and re-hash.
- **Still to run (GPU, after training):** the two point-prompted W2 v3 HCC rows of this lesion with the corrected label.
