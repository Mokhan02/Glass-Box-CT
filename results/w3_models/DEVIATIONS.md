## 4. Per-arm bootstrap seed in `scripts/w3_analyze.py` (2026-10-20; researcher's instruction; before model D's analysis)
- **Why:** the analysis used one random sequence across all arms in alphabetical order, so an arm's bootstrap CI depended on which other arms were loaded (the VISTA reference row read [+24.0, +65.2] alone and [+24.3, +64.7] beside model A). Point estimates and verdicts were never affected.
- **Change:** each arm's bootstrap uses `np.random.default_rng(arm_seed(arm))`, with `arm_seed` = first 8 hex digits of SHA-256 of the arm name (stable across runs, machines and Python versions); an arm's results no longer depend on the other arms (unit test). 1000 resamples, percentile CIs, case-level resampling unchanged. `scripts/w2v3_analyze.py` (shared statistic helpers) is unchanged.
- **Re-run:** the model A (swin, shipped and raw) and VISTA reference-row analyses (primary, as-converted and excluded-case sensitivities) were re-run with the pinned seeds on CPU: **no verdict or model-level label changes**; CIs move by at most about 2 points at an end. The earlier shared-seed outputs are kept in `analysis_shared_seed_superseded/` and `reference_row/shared_seed_superseded/`; the pinned-seed outputs are the reported ones.
- Re-hashed in `code_hashes.txt` ("Deviation 4").
- **Decision logged:** the model A kidney arm (secondary, "possibly seen in training") is **skipped** by the researcher: in-distribution for model A and kidney was covered by W2. Not run.

## 8. Stage 2 session 1 (2026-10-22 to 23): deviations found while running the first session (all before any M1 cohort number was seen)
- **Sanity check 1 (VISTA probe-table reproduction) is near-exact, not exact**, in the current environment (new instance; stored table from an earlier environment): 228 cells compared, 47 differ by at most 0.0062 (small strata, bottleneck, raw-HU rows); the primary row is exact to the 4 decimals shown (0.5873) and the VISTA verdict is the same (LOST LATE; decoder_F rate, margin and CIs agree to the 4th decimal); the analysis gives identical tables in two interpreters (numpy 1.26.4 and 2.2.6, scikit-learn 1.7.2). This is the same limitation the researcher accepted in W2-M (DEVIATION 1); the PREREG says "exactly", so it is logged here, not hidden, and the session continued under that precedent. M1 numbers carry this note.
- **Hook-check test design:** the first propagation test added a constant offset, which LayerNorm (A) and InstanceNorm-after-convolution (D) cancel, so deeper layers did not change; the test was replaced by a seeded channel-varying edit (0.5 x the tensor's std) and then passed for A and D (A: hidden states 3 and 4 change by about 1.0, logits by 22; D: skip 4 and the first decoder stage change, logits by 7.2; both consumers confirmed). The D "reproduces Stage 1" part initially failed because nnU-Net's library prediction call spawns processes that re-imported the script; it now uses the same `nnUNetv2_predict` command as Stage 1 (coverage difference <= 4e-5 on 3 cases; A <= 3e-5). U-Net shapes passed.
- **Extraction code fixes found in the 3-case smoke tests:** a forward hook that returned a value replaced the Swin module's output (fixed to return nothing); a wrong nnU-Net method name. No cohort result existed at that point.
- **Model D extraction cost:** the first smoke test projected about 200 s per case (about 4 h for 75 cases against the PREREG estimate of 1.2 h, above the 1.25 x stop threshold). Profiling showed 98 of 218 s in the per-token percentile loop of the raw-HU features, 60 s in the mirrored default prediction and the rest in nnU-Net preprocessing. Fix: the percentile features for cells above 8 voxels use a regular `cell // 8` subsample (exact for model A and VISTA, a 2x subsample for model D's 16-voxel cells; only D's raw-HU CONTROL features change slightly), and the extraction is sharded over three processes; one shard ran out of GPU memory with three shards plus the U-Net run and was restarted (outputs are per case, nothing lost); the model A U-Net run was paused so D could have the GPU. The GPU, not the CPU, is the limit (mirrored prediction), so the wall time is longer than the estimate. Actual timings (session 1, one A10): model A extraction about 60 to 80 min for 75 cases (as estimated); model D extraction about 2 h 20 min wall with three shards (estimate 1.2 h); the A U-Net run about 50 min, in two pieces (paused while D ran); the whole session about 4.5 h including the hook checks and smoke tests; the GPU was idle from 01:42 UTC (9:42 PM New York).
