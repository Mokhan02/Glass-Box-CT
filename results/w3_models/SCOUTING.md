# W3 model scouting (CPU only, no GPU, no downloads of weights, no PREREG yet)

Date: 2026-10-18. Question: which open CT segmentation models can replicate the brightness-dependence audit (bright-vs-dark tumour detection and Dice gap on HCC-TACE-Seg, then the mid-encoder mechanism) with a different architecture and training data from VISTA-3D?
Sources were read with web fetches of the repos, model cards, papers and raw source files, and the Hugging Face and GitHub APIs (metadata only). **Text in quotation marks is verbatim from the source; everything else is my reading.** Items marked **TO VERIFY** were not found in a primary source and must be checked before a PREREG relies on them. The fetch tool sometimes summarised long pages, so the dataset lists are as read from the cited table, not independently recounted.

## A. CLIP-Driven Universal Model (Liu et al., ICCV 2023; github.com/ljwztc/CLIP-Driven-Universal-Model)
1. **Weights and licence.** README: two checkpoints on Hugging Face, "U-Net, 19.08M parameters" and "Swin UNETR, 62.19M parameters" (HF API sizes 77.8 MB and 758.9 MB). Licence conflict: the repository `LICENSE` reads "© The Johns Hopkins University. This work is openly licensed via CC BY-NC-ND. Creative Commons Attribution-NonCommercial-NoDerivatives 4.0 International Public License", while the Hugging Face weights repo is tagged `license:mit`. Reading: research use is non-commercial and fine; "NoDerivatives" means we should not publish modified checkpoints (hooking at inference time does not modify the weights). **Researcher decision (2026-10-19): model A is approved for non-commercial research use only; no edited checkpoints are published; it never enters the product or main branch.** Citations for the conflict: the code repository licence text, `https://raw.githubusercontent.com/ljwztc/CLIP-Driven-Universal-Model/main/LICENSE` (CC BY-NC-ND 4.0, Johns Hopkins University), against the weights repository metadata, `https://huggingface.co/api/models/ljwztc/CLIP-Driven-Universal-Model` (tags `license:mit`) and the model page `https://huggingface.co/ljwztc/CLIP-Driven-Universal-Model`. The weights licence (MIT) and the code licence (CC BY-NC-ND) were therefore treated as conflicting and the stricter terms apply.
2. **Training data.** Paper (arXiv 2301.00785, Table 7): "14 datasets, 3,410 CT scans": Pancreas-CT 82, LiTS 201, KiTS 300, AbdomenCT-1K 1,000, CT-ORG 140, CHAOS 40, MSD CT tasks 947 (Liver, Lung, Pancreas, HepaticVessel, Spleen, Colon), BTCV 50, AMOS22 500, WORD 150. External evaluation: 3D-IRCADb, JHH (private), TotalSegmentator. HCC-TACE-Seg and CRLM-CT are not in the list: **held-out for HCC and CRLM**. KiTS (300 cases, "Kidney, Kidney Tumor") is in training; its size matches the whole KiTS19 release (210 train + 90 test, which contains C4KC-KiTS; the README gives no year, so the version is **TO VERIFY**), and AbdomenCT-1K also contains KiTS and LiTS images (Ma et al.: "KiTS (300 cases)", "LiTS (201 cases)"): **C4KC-KiTS should be treated as not held-out.** Liver tumour supervision comes from LiTS and MSD Liver and HepaticVessel, like VISTA-3D, so the training-data hypothesis of W1 applies to it.
3. **Outputs.** README "Current Template" lists 32 labels including "26: Kidney Tumor", "27: Liver Tumor", "32: Kidney Cyst". No click is needed (fixed class embeddings per class); `pred_pseudo.py` saves `organ_list = [i for i in range(1,33)]` after "pred_sigmoid = F.sigmoid(pred)" and a threshold. The paper says "the CLIP embedding only depends on the dictionary, which is fixed."
4. **Architecture.** `Universal_model.py`: `backbone` in `'swinunetr'`, `'unet'`, `'dints'`, `'unetpp'`; SwinUNETR built with `feature_size=48`, `nn.Conv3d(48, 8, kernel_size=1)`, `nn.GroupNorm(16, 768)`; per-class dynamic head `weight_nums 8*8, 8*8, 8*1`. `model/SwinUNETR.py` (MONAI-style): `patch_size = ensure_tuple_rep(2, ...)`, `depths (2, 2, 2, 2)`, `"dim=int(embed_dim * 2**i_layer)"`, returns `hidden_states_out`. With feature_size 48 the five encoder outputs are 48, 96, 192, 384, 768 channels at strides 2, 4, 8, 16, 32 (derived, **TO VERIFY against the checkpoint shapes**: the file's own default is 24). **Candidate hook: `hidden_states_out[2]`, 192 channels at stride 8 = 12 mm at 1.5 mm spacing, 12^3 tokens per 96^3 window**: the same width and grid as VISTA-3D's pooled mid tokens. Note: the repo's default `encoding` is `'rand_embedding'`; the word-embedding buffer is part of the checkpoint (**TO VERIFY** which encoding the released checkpoint uses).
5. **Preprocessing.** Paper: "re-slice each scan to the same voxel size of 1.5x1.5x1.5 mm3", "truncate the intensity in each scan to the range [-175,250]", "a patch size of 96x96x96". `pred_pseudo.py`: `--roi_x 96`, `--space_x 1.5`, `--a_min -175`, `sliding_window_inference(image, (roi...), 1, model, overlap=0.5, mode='gaussian')`. Input is a directory of `.nii.gz`, so it runs on our converted HCC-TACE-Seg NIfTIs.

## B. SAT (Zhao et al., arXiv 2312.17183; github.com/zhaoziheng/SAT)
1. **Weights and licence.** HF `zzh99/SAT`: `Nano/nano.pth` 1,503 MB, `Nano/nano_text_encoder.pth` 443 MB, `Pro/SAT_Pro.pth` 5,905 MB (+ text encoder 443 MB). SAT-Pro alone exceeds the 5 GB download guard, and its inference memory (below) rules it out anyway. **No licence stated** anywhere (no LICENSE file, GitHub API licence null, no HF tag). SAT-DS README: "we respect and adhere to the licenses of all the datasets."
2. **Training data.** SAT-DS: "72 diverse publicly available medical segmentation datasets", "497 segmentation classes", "22,186 scans" (CT, MR, PET). `data/dataset_config/72.json` keys (primary) include `KiTS23`, `MSD_Liver`, `MSD_HepaticVessel`, `AbdomenCT1K`, `CT_ORG`, `SLIVER07`, `Couinaud_Liver`, `TotalSegmentator_*`, `WORD`, `AMOS22_CT`. **No HCC-TACE-Seg, no CRLM, no C4KC-KiTS / KiTS19 / KiTS21, no LiTS as its own entry.** HCC-TACE-Seg and CRLM held-out. C4KC-KiTS: AbdomenCT1K contains the 300 KiTS cases (so the images are probably seen) and KiTS23 has 489 cases (SAT-DS table); whether KiTS23 includes the KiTS19 cases was not stated in the KiTS23 README: **TO VERIFY**.
3. **Outputs.** "SAT requires only a single text prompt to segment the entire 3D scan"; no spatial prompt. Table 10 lists "Liver tumor" under CT lesions; "kidney tumor" was not found in the readable text (Table 12 not in the fetched HTML): **TO VERIFY** the exact strings.
4. **Architecture.** `model/maskformer.py`: `PlainConvUNet(input_channels=3, n_stages=6, features_per_stage=(64, 64, 128, 256, 512, 768), strides=(1, 2, 2, 2, 2, 2), n_conv_per_stage=(2, 2, 2, 2, 2, 2) ...)` for the Nano UNET, plus "6 standard transformer decoders" and a BERT-family text encoder. Candidate hook: encoder stage 3 (256 channels, stride 8). Patch 288x288x96, so strides are anisotropic in physical units (see 5).
5. **Preprocessing.** Paper appendix: "We take voxel spacing as 1x1x3 mm2 and patch size 288x288x96" (garbled in the source, **TO VERIFY**); CT "truncated to [-500, 1000]" then z-score (from the fetched text). Inference needs a `jsonl` with image path and label names.
6. **Practical blocker.** README: inference memory "about 34GB (SAT-Pro, batch 1)" and "24GB (SAT-Nano, batch 1)"; the A10 has 23 GB. SAT-Nano is borderline and SAT-Pro does not fit.

## C. SegVol (Du et al., arXiv 2311.13385; huggingface.co/BAAI/SegVol)
1. **Weights and licence.** HF files: `pytorch_model.bin` 723.7 MB, `vit_pretrain.ckpt` 352.8 MB, `model_segvol_single.py`, tokenizer files. GitHub (BAAI-DCAI/SegVol) licence: MIT (API). HF card: no licence tag.
2. **Training data.** README: "By training on 90k unlabeled Computed Tomography (CT) volumes and 6k labeled CTs"; the paper's Table 4 lists the labelled datasets, including "3D-IRCADB: Liver and liver tumor (20)", "AbdomenCT-1k (1000)", "KiTS19: Kidney and kidney tumor (210)", "KiTS23: Kidney, kidney tumor, and kidney cyst (489)", "MSD-Liver: Liver and liver tumor (131)", "MSD-HepaticVessel: Hepatic vessel and liver tumor (303)". As read, HCC-TACE-Seg and CRLM are not in it (held-out); **KiTS19 (210) is in it, which is exactly C4KC-KiTS: not held-out.** The README and paper disagree on the volume counts (90k vs 96k).
3. **Outputs.** Prompts: "accepts point, box, and text prompts while output volumetric segmentation". The code asserts `'Drive SegVol using at least one type of prompt'`. The paper reports text-only results (so no click is possible but a text prompt is needed); the demo config uses categories such as "liver", "kidney". Liver tumour appears in the paper's results (Table 7); kidney tumour has training labels but no results row. **TO VERIFY** the exact category strings.
4. **Architecture.** HF `config.json`: `patch_size [4, 16, 16]`, `spatial_size [32, 256, 256]`; paper: "3D ViT; patch size=(4, 16, 16), layers number=12, heads number=12, hidden size=768". Candidate hook: block 6 output (768-d). Tokens form an 8x16x16 grid on the zoomed-out volume, about 25 mm in-plane and 30 mm in z for typical fields of view, which is very coarse for lesions of 10 to 60 mm (zoom-in refinement is finer).
5. **Preprocessing.** `SegVolProcessor` in `model_segvol_single.py`: foreground normalisation clipping at the 0.05th and 99.95th percentiles, `Resized` to `spatial_size`, a zoom-out transform and zoom-in; **no physical-spacing resampling was found**. The demo processor takes a ground-truth mask to build prompts, so a dummy or the real GT is needed.

## D. nnU-Net v2, self-trained on MSD Task03 (github.com/MIC-DKFZ/nnUNet)
1. **Weights.** None to download. MSD Task03 (131 labelled cases, label 1 liver, label 2 tumour) is already extracted on the persistent filesystem (W1). Code licence Apache-2.0.
2. **Training data.** Only Task03: HCC-TACE-Seg and CRLM-CT are held-out by construction; there is no kidney model (the only kidney tumour set here is KiTS19 = C4KC-KiTS, which cannot be held out).
3. **Outputs.** Automatic: the tumour channel (label 2) of the 3d_fullres network, no click. No kidney tumour.
4. **Architecture.** `default_experiment_planner.py`: `UNet_class = PlainConvUNet`, `UNet_base_num_features = 32`, `UNet_max_features_3d = 320`, `UNet_vram_target_GB` default 8, `UNet_featuremap_min_edge_length = 4`, target spacing "np.percentile(spacings, 50, 0)" (median), `UNet_min_batch_size = 2`. The Task03 plan (patch size, stages, strides) is **not yet generated**: it needs `nnUNetv2_extract_fingerprint` and `nnUNetv2_plan_experiment` (CPU, minutes; the instance holding the data was not reachable during scouting). Candidate hook: the encoder stage with 128 to 256 channels (stride 4 to 8, about 4 to 8 mm), chosen once the plan exists.
5. **Preprocessing.** `CTNormalization`: clip at `percentile_00_5` and `percentile_99_5` of the foreground intensity properties, then subtract `mean` and divide by `std`; spacing = dataset median; inference via `nnUNetv2_predict` on NIfTIs named `*_0000.nii.gz`, so HCC-TACE-Seg as we convert it works.
6. **Training time on an A10 (estimate, not measured).** Defaults verified: `num_epochs = 1000`, `num_iterations_per_epoch = 250`, `num_val_iterations_per_epoch = 50`; shorter trainers exist (`nnUNetTrainer_100epochs`, `_250epochs`, `_500epochs`, `_750epochs`, `_2000epochs`). nnU-Net's benchmark doc points to an external spreadsheet (no A10 numbers on the page) and offers `nnUNetTrainerBenchmark_5epochs`. My estimate, from typical nnU-Net 3d_fullres speeds on RTX 3090/A100-class cards (about 90 to 150 s per epoch) and an A10's lower memory bandwidth (about 1.2 to 1.6 times slower): **1000 epochs about 30 to 60 h for one fold; 250 epochs about 8 to 15 h; 100 epochs about 3 to 6 h.** **To measure: the 5-epoch benchmark trainer, about 10 minutes of GPU, which needs your OK.** Hardware doc: training needs "at least 10 GB" VRAM and at least 6 CPU cores.
7. **Is a fixed fold acceptable?** Yes for the audit, if declared in the PREREG: the evaluation set is external (HCC-TACE-Seg), so the fold only decides which 105 of 131 Task03 cases train the model and gives 26 in-domain validation cases as a sanity check. Training on all 131 cases (`-f all`) would remove that sanity check for 25 more training cases. I would recommend fold 0 with a fixed seed, plus the in-domain Dice on its validation cases, reported but not used for selection.

## Recommendation: A and D, in that order of availability
- **A (CLIP-Driven Universal Model, Swin UNETR).** Automatic liver and kidney tumour outputs, public weights (759 MB), a different encoder family from VISTA-3D with a 192-channel, 12 mm stage that matches the existing probe, LEACE and projection code, HCC and CRLM held-out, and the same MSD/LiTS liver supervision as VISTA-3D (so its liver result tests whether the failure follows the training data). Caveats: the licence conflict (needs your confirmation), kidney is not held-out (C4KC-KiTS in training), and the checkpoint's embedding encoding and Swin feature size need checking at load time.
- **D (nnU-Net self-trained on Task03).** Fully known training data, no overlap with any evaluation cohort, a plain CNN (different from both VISTA-3D and the Swin model), and it doubles as the base model for the later training-intervention workstream (W5). Caveats: liver only, and the training cost (the main risk): the full schedule is too long for one session, so a shorter schedule is a design decision you need to make.
- **Why not SAT:** its inference memory (about 24 GB for Nano, 34 GB for Pro) exceeds the A10, it has no licence, spacing and strides are anisotropic, and its kidney/liver class strings are unverified. **Why not SegVol (now):** its tokens are about 25 mm and it resamples volumes non-physically, so the mid-encoder probe would be too coarse for lesions of 10 to 60 mm; its KiTS19 training exposure is explicit; it always needs a prompt. Either can be revisited as a third model if A and D disagree.

## Draft W3 plan (each stage with its own PREREG, written and committed before any run)
**Gate 0 (CPU, no GPU): load-time checks.** Download the A weights (759 MB, under the 5 GB guard) and check checkpoint tensor shapes (feature size, class embeddings); generate the nnU-Net Task03 plan on CPU; confirm the hook shapes. Report; stop.
**Stage 1: behaviour (per model).** Cohort: HCC-TACE-Seg UID route, 75 cases, 86 lesions (the W1/W2 reference set), same lesion definition and contrast function (`glassbox/audit/contrast.py`), bright = lesion minus liver 5 to 20 mm shell > 0 HU. Model A: automatic class 27, 1.5 mm spacing, sigmoid > 0.5 (as the authors), no click. Model D: the trained network's tumour label. Outcomes: lesion detection (coverage >= 10%), lesion Dice, coverage, RECIST sum-of-diameters error; primary = Dice gap (dark minus bright) with a case-level bootstrap CI and the W2 v3 verdict rule (GAP / NO MEANINGFUL GAP / INCONCLUSIVE, margin 0.10); secondaries: detection gap, size-adjusted gap, failure modes. Model A on C4KC-KiTS kidney tumours (class 26) only as a flagged-in-distribution replication of W2. Estimated GPU: model A about 20 to 30 min; model D inference minutes (training is separate, see below).
**Model D training (its own PREREG).** Fixed fold 0, fixed seed, the chosen trainer variant, the 5-epoch benchmark first (needs your OK), in-domain validation Dice on the fold's 26 cases reported as a sanity check, and the W1 audit already shows the Task03 bright-tumour share is 1.1% [0.0, 2.8].
**Stage 2: mechanism (per model, only if Stage 1 shows a bright-vs-dark gap; its own PREREG).** (i) Voxel probe at the hook point with the random-init network and raw-HU controls (A: Swin `hidden_states_out[2]`, D: a mid-encoder stage), patient-level splits, same token definitions as the HCC voxel probe; (ii) cross-fitted rank-1 LEACE erasure with random and HU controls and an organ guard; (iii) brightness: the paired HU counterfactual on dark tumours and the projection drop on the probe direction (exploratory), as in the HCC bridge. Cross-model comparison with VISTA-3D is descriptive.
**Dependencies and order.** Gate 0, then the model D PREREG and benchmark (training is the long pole and can run while model A's Stage 1 is written), then Stage 1 for A and D, then Stage 2 where indicated.

## Gate 0 results (2026-10-19; local CPU part for model A and the published nnU-Net references; the instance part is below)
**Model A, checkpoints and shapes** (`scripts/w3_gate0_modelA.py`, `gate0/modelA_shapes.json`; weights 758,907,945 and 77,792,727 bytes, matching the Hugging Face file sizes; repo commit and checkpoint sha256 in the JSON).
- Swin UNETR checkpoint: 170 of 170 keys loaded into the repo's own `Universal_model` (the key remapping of `pred_pseudo.py`), no missing or unexpected keys, no shape mismatches, 62.6 M parameters, epoch 450. U-Net checkpoint: 117 of 117 keys, 19.4 M parameters, epoch 400.
- **The checkpoints carry the CLIP class embedding:** `organ_embedding` [32, 512] is in the checkpoint and equals the repo's `pretrained_weights/txt_encoding.pth` (this resolves the earlier "which encoding" question; the released model uses `word_embedding`).
- **Class indices verified from the repo's `utils.py`:** `NUM_CLASS = 32`; `ORGAN_NAME[25] = 'Kidney Tumor'` (class 26) and `ORGAN_NAME[26] = 'Liver Tumor'` (class 27), so output channels 25 and 26 (0-based); threshold 0.5 for both; post-processing constants `TUMOR_ORGAN` Liver Tumor -> [6], Kidney Tumor -> [2, 3], `TUMOR_NUM` 20 and 5, `TUMOR_SIZE` 20 and 80.
- **Hook point confirmed on a dummy 96^3 window:** `backbone.swinViT` returns hidden states of shapes (48, 48^3), (96, 24^3), **(192, 12^3)**, (384, 6^3), (768, 3^3); the chosen hook is output[2], 192 channels at stride 8 (12 mm at 1.5 mm spacing, 12^3 tokens per window), as predicted from the code. The output shape is [1, 32, 96, 96, 96].
**Published nnU-Net Task03 references** (Isensee et al., arXiv 1904.08128, supplementary Tables F.5 and F.6, read from the paper PDF): five-fold cross-validation on the 131 training cases: 2D liver 0.9547 / cancer 0.5637; **3D full resolution liver 0.9571 / cancer 0.6372**; 3D low resolution 0.9563 / 0.6028; 3D cascade 0.9600 / 0.6386; best ensemble 0.9613 / 0.6564; test set 0.96 / 0.76. The nnU-Net v1 plan for this task: target spacing 1 x 0.7676 x 0.7676 mm, patch 128 x 128 x 128, batch size 2, CT normalisation "Clip to [-17, 201], then subtract 99.40 and finally divide by 39.36". The v2 plan for our data is generated in the instance part.
