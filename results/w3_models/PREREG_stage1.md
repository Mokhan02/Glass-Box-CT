# Pre-registration W3 Stage 1: does the bright-versus-dark segmentation gap appear in other models?

Status: APPROVED (2026-10-20) with three edits (alignment check on every case; VISTA-3D reference row; run order), committed on `research/roadmap` with the runners, the analysis script and their hashes (`results/w3_models/code_hashes.txt`) BEFORE any Stage 1 cohort run. Before the commit the runners were smoke-tested on 2 HCC cases (model A) and 2 HCC cases (reference row) as a pipeline check only: those numbers are not results and the same cases are re-run in the main run. Deviations go to `results/w3_models/DEVIATIONS.md`. **Inclusion or exclusion changes need the researcher's sign-off before they are applied, even pre-analysis.** Nothing here touches `main`; model A is non-commercial research use only, no edited checkpoints are published, and it never enters the product or main branch.

## Question
VISTA-3D segments tumours that are brighter than the surrounding liver worse than darker ones (W1, W2). Does the same bright-versus-dark gap appear in two other models with different architectures and training data?

## Models
**A. CLIP-Driven Universal Model** (Liu et al., ICCV 2023; Gate 0 verified from the repo and the checkpoints, `results/w3_models/gate0/modelA_shapes.json`).
- **Primary checkpoint:** `clip_driven_universal_swin_unetr.pth` (sha256 `cde35d9c...`, 62.6 M parameters, epoch 450); automatic output, no click: class 27 "Liver Tumor" (output channel 26). The released checkpoint carries the CLIP class embedding (`organ_embedding` [32, 512] equals the repo's `txt_encoding.pth`).
- **Sensitivity checkpoint:** `clip_driven_universal_unet.pth` (sha256 `bfa7482e...`, 19.4 M parameters, epoch 400).
- **Inference = the authors' default pipeline as shipped (`pred_pseudo.py`), including its post-processing; this is the primary,** mirroring how VISTA-3D was evaluated as shipped. Steps (verified from the repo): orientation RAS, 1.5 mm isotropic spacing (bilinear), HU clipped to [-175, 250] and scaled to [0, 1], foreground crop, 96^3 Gaussian sliding window with overlap 0.5, sigmoid, threshold 0.5 (`THRESHOLD_DIC['Liver Tumor'] = 0.5`), then `organ_post_process`, whose class-27 branch is: (a) take the predicted liver (class 6) and keep its largest connected component (`merge_and_top_organ`, `TUMOR_ORGAN['Liver Tumor'] = [6]`); (b) binary closing with a 5x5x5 cube; (c) binary dilation with a 5x5x5 cube; (d) keep only tumour voxels inside that region (`organ_region_filter_out`). The top-k and minimum-size filters for tumours (`TUMOR_NUM`, `TUMOR_SIZE`) are commented out in the shipped code and are NOT applied. The result is mapped back to the input grid with nearest-neighbour inversion (`save_results`).
- **Sensitivity = the raw thresholded sigmoid (no post-processing).** **If the shipped and raw variants disagree** (a different model-level label in the primary, or a different verdict category for either metric), the report attributes the difference to the responsible step by evaluating the cumulative variants raw threshold -> (a) intersect with the predicted liver's largest component -> (a)+(b) closed region -> (a)+(b)+(c) dilated region = shipped, and names the step with the largest change in the Dice gap and in the detection gap.
- **Gate 0 on one HCC case (HCC_004_414785):** the shipped pipeline ran unchanged under the pinned repo commit with MONAI 0.9.0 and NumPy 1.26.4 over the instance's torch 2.14.1 (the repo's own pins did not run on NumPy 2); class 27 output non-empty (64.4 mL, array aligned with the input grid: liver Dice 0.936 against the ground-truth liver and 0.577 when flipped in z, 97.5% of predicted tumour inside the ground-truth liver; the saved NIfTI header affine is stale (1.5 mm RAS metadata on the original-grid array), so evaluation uses array indices on the input grid and ignores that header); running `organ_post_process` for class 27 alone is identical to running it for all 32 classes (so the cohort runner may run only class 27); on this case none of the post-processing steps changed the mask (19,108 voxels at every step); the hook `backbone.swinViT` output[2] was (1, 192, 12, 12, 12) on all 24 real windows.
- **Kidney arm (secondary):** class 26 "Kidney Tumor" on C4KC-KiTS, same rules, **flagged "possibly seen in training"**: A's training list contains KiTS (300 cases) and AbdomenCT-1K; which cases were seen is unknown.

**D. nnU-Net v2, self-trained on MSD Task03 (liver and tumour, 131 cases)**, 3d_fullres, default `nnUNetPlans` (PlainConvUNet; Gate 0 plan: 3d_fullres, spacing 1.0 x 0.768 x 0.768 mm, patch 128^3, batch 2, 6 stages, features 32/64/128/256/320/320, CT normalisation with foreground clip [-15, 197] HU (0.5 and 99.5 percentiles), mean 99.5, std 37.1; `gate0/nnunet_task03_nnUNetPlans.json`, `nnunet_task03_dataset_fingerprint.json`), **fold 0**, fixed seed (a thin trainer subclass seeds Python, NumPy and torch before construction; recorded), nnU-Net's own `splits_final.json` for the fold.
- **Schedule rule (fixed now): 1000 epochs if the projected training time is <= 24 h on the chosen GPU; otherwise 250 epochs, for ALL self-trained models in W3 and W5.** The projection comes from the Gate 0 benchmark (measured seconds per epoch on the chosen GPU, with the validation iterations) and is written into `DEVIATIONS.md` as a dated note before training starts. Benchmark result (Gate 0, `results/w3_models/gate0/nnunet_benchmark_result.json`, `nnunet_benchmark_epochs.txt`): on one NVIDIA A10 (torch 2.14.1+cu130, cuDNN 9.24, nnunetv2 2.8.1, `nnUNetTrainerBenchmark_5epochs`, 3d_fullres fold 0, batch 2, patch 128^3, 250 train + 50 validation iterations per epoch) the first epoch took 134.9 s (torch.compile warm-up) and epochs 1 to 4 took 60.6, 60.9, 61.3 and 61.5 s (fastest 60.56 s, mean 61.09 s). Projection at 61.1 s/epoch: **250 epochs = 4.2 h; 1000 epochs = 17.0 h** (about 17.3 h with the warm-up, final validation and checkpointing; benchmark epochs include the per-epoch validation iterations). **1000 epochs is <= 24 h, so the schedule is 1000 epochs for ALL self-trained models in W3 and W5 on an A10.** A faster GPU would not change the decision (it can only shorten it).
- **Sanity gate (stop and report before any HCC inference):** the fold-0 validation Dice for the Task03 tumour class and liver class (nnU-Net's own validation on the 27 held-out Task03 cases (`gate0/nnunet_task03_splits_final.json`: 104 train, 27 validation)) is compared with the published nnU-Net five-fold cross-validation on the same 131 cases (Isensee et al., arXiv 1904.08128, Table F.6: 3D full resolution liver 0.9571, cancer 0.6372; the ensemble 0.6564; test set 0.96 / 0.76). **"Far below" is defined here as fold-0 validation tumour Dice more than 0.10 below 0.6372 (below 0.537) or liver Dice below 0.93; if so, stop and report.** Caveats stated in advance: a single fold scatters around the five-fold mean, and the 250-epoch schedule can lower the tumour Dice; neither changes the rule, and a stop means the researcher decides.
- Inference: `nnUNetv2_predict` with the fold-0 checkpoint, default settings (test-time mirroring on, step size 0.5), on our converted HCC NIfTIs; the tumour label (2), resampled to the original grid.
- **No kidney model:** the only kidney tumour set available is KiTS19 = C4KC-KiTS itself.

## Amendment 2 (2026-10-20, approved by the researcher; decided after seeing which cases failed the organ-Dice gate but BEFORE any tumour metric of any model A or model D cohort run): the alignment gate becomes an alignment check
**Why:** the original gate (organ Dice >= 0.85 against the GT organ, edit 1) stopped model A after 33 cases on HCC_019_773068, HCC_022_228695 and HCC_043_848214. The diagnostic (`results/w3_models/stage1/alignment_diag/`, no tumour metric) showed that HCC_019's failure was a displaced ground-truth label (corrected in Amendment 1) and that HCC_022 and HCC_043 are correctly placed but under- or over-segmented livers (centroid offsets 13.4 and 9.8 mm). Organ Dice measures segmentation quality, not alignment, so it is the wrong quantity to gate on.
**New gate (applies identically to model A, model D and the kidney arm; array indices, GT spacing for mm):** the case passes if (1) the output array has the input array's shape, (2) no axis flip of the predicted organ raises its Dice against the GT organ (orientation), and (3) the predicted-vs-GT organ centroid offset on the annotated slices is <= 15 mm (the limit of the diagnostic rule, fixed before that diagnostic ran, not tuned: HCC_022 passes at 13.4 mm, i.e. narrowly). **Stop and report if more than 2 cases fail the check.** Organ Dice is still reported for every case and cases below 0.85 are listed, but it no longer gates. Organ for model A = the shipped predicted organ (liver, class 6; kidney arm classes 2 and 3); for model D = nnU-Net label >= 1.
**Cases that fail the Dice flag stay in the primary analysis. The sensitivity analysis excludes the cases with organ Dice < 0.85 (and any case that fails the check),** reported beside the primary. The trigger the researcher set for proposing this amendment (all 3 failures aligned-but-undersegmented) was not literally met because HCC_019 was a label displacement; the amendment was applied at the researcher's explicit instruction after Amendment 1 corrected that case. The 33 cases of the halted run are re-run; none of their tumour metrics was computed or used.
**Run order fixed by the researcher:** (1) re-run the two W2 v3 HCC_019 rows with the corrected label (`scripts/w2v3_rerun_hcc019.py`, with a determinism check on the as-converted label against the stored rows), (2) model A (swin, shipped pipeline) on the full HCC cohort under this gate, committed analysis, verdict reported as soon as it is in, (3) model D on the HCC cohort through the same gate, the same analysis and the same VISTA-3D reference row, verdict reported. The model A secondaries (U-Net checkpoint, kidney arm) are not part of this run order and stay pending.

**Correction to Amendment 2 (2026-10-20, Deviation 5 in `results/w3_models/DEVIATIONS.md`, decided before any model D tumour metric):** the researcher's intended gate is a **Dice-maximising translation test: the best translation of the predicted organ (search +-40 mm in-plane, +-7.5 mm through-plane) must be <= 5 mm per axis; a case is MISALIGNED if the best shift exceeds 5 mm on some axis AND raises the organ Dice by >= 0.05 (\"substantially\"; the margin of the diagnostic rule), MODEL-SIDE if the shift exceeds 5 mm but no translation substantially fixes it (stray blobs or a genuine organ failure), ALIGNED otherwise.** The shape and axis-flip checks stay. The stop rule stays (stop and report if more than 2 cases are MISALIGNED or fail shape / flip). MODEL-SIDE cases are QUALITY-FLAGGED: they stay in the primary analysis and the sensitivity analysis excludes them. The centroid offset (<= 15 mm) that was committed in Amendment 2 is kept only as a descriptive column. No largest-connected-component filtering is applied to any model's predictions.
## Outcomes
Per lesion: **detection** = coverage >= 0.10 (share of ground-truth lesion voxels predicted); **Dice** (`dice_full`: the whole prediction on annotated slices against the lesion); coverage; Dice within 10 mm; per case the RECIST sum-of-diameters error (largest overlapping predicted component, a miss counts as 0 mm).

## Primary analysis (per model)
- **Detection gap** = detection rate in dark lesions minus in bright lesions; **Dice gap** = mean Dice in dark minus in bright lesions (positive = bright segmented worse). Case-level bootstrap, 1000 resamples, seed 0, percentile 95% CIs.
- **Verdict per metric (the W2 v3 structure, margin 0.10 for both; for detection this is 10 percentage points):** **GAP** if CI lower > 0 and the point estimate >= 0.10; **NO MEANINGFUL GAP** if CI upper < 0.10; **INCONCLUSIVE** otherwise, in that order.
- **Model-level label:** "GAP (detection and Dice)", "GAP (Dice only)", "GAP (detection only)", "NO MEANINGFUL GAP (both)", or "INCONCLUSIVE". Models are reported separately; replication = both A and D reach "GAP (detection and Dice)"; no pooling.

## Secondary (reported with the primary, never instead of it)
- **Size-adjusted:** OLS of Dice on `bright` and log(diameter) and an unpenalised logistic regression of detection on `bright` and log(diameter), each with a case-clustered bootstrap CI; the adjusted effect is stated next to the headline, and if it disappears (CI includes 0 or has the opposite sign) that is stated beside it. Gaps within strata (<30, 30 to 60, >60 mm), the coverage gap, the Dice-within-10-mm gap, and RECIST bias by group are descriptive.
- **Model A sensitivities:** the raw thresholded sigmoid (with the step attribution above) and the U-Net checkpoint (run through the shipped pipeline).
- **Model A kidney arm (C4KC-KiTS, 219 lesions, 53 bright, class 26):** the same metrics and rules, labelled secondary and "possibly seen in training".

## Training-data audit note
- **A's** liver-tumour supervision comes from the MSD/LiTS family (LiTS 201 cases, MSD Liver 131, MSD HepaticVessel 303 per its paper's Table 7; 3D-IRCADb is external), so the W1 audit applies only in part: W1 measured MSD Task03 (bright share 1.1% [0.0, 2.8], 184 lesions) and CRML-CT, not LiTS or HepaticVessel tumours (LiTS images overlap Task03's).
- **D's** supervision is Task03 only (W1: 1.1% [0.0, 2.8] bright).
- Reading rule (not a hypothesis test): a bright-versus-dark gap in these models is consistent with the training-data explanation from W1, and a null would count against a simple version of it; neither shows causation (that is W5).

## Gate to Stage 2
Stage 2 (voxel probe with random-init and raw-HU controls, cross-fitted LEACE, the brightness projection) is only considered for a model whose primary label contains GAP, under its own PREREG.

## Named confounds and limits
HCC-TACE-Seg mixes acquisitions and its contrast phase cannot be labelled; tumour type differs from the training sets; the models differ in baseline Dice, so absolute gaps are compared with care; threshold and post-processing choices are fixed above; A was not trained on HCC-TACE-Seg but its training data may contain similar cases (not verifiable); D is a single fold with one seed and possibly a shortened schedule; the kidney arm is not held-out; size is related to brightness (hence the size-adjusted secondary); no multiplicity correction across models and metrics.

## GPU time estimates
Smoke-test timing on the A10: model A about 25 to 31 s per case (HCC), so about 35 min for the 75 HCC cases per checkpoint and about 1.7 h for the 210-case kidney arm; the VISTA-3D reference row about 7 s per case, about 9 min. Model D inference: about 25 min. Model D training: about 17.3 h at 1000 epochs (measured 61.1 s/epoch on the A10, Gate 0 benchmark; 4.2 h if the schedule were 250 epochs); W5 retrains use the same schedule per model. Epochs may be slower while the model A secondaries share the GPU.
